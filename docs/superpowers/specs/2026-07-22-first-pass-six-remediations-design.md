# 六项整改第一版规格

日期：2026-07-22

状态：已确认实施（用户指令：“开始 1，2，3，4，5，6 的整改，先做第一版”）

## 假设

1. 机器人继续只在当前 Windows 电脑运行，不迁移云服务器。
2. 现有 `.env` 是唯一密钥载体；整改不得读取、打印、改写或复制其中内容。
3. “第一版”优先解决稳定运行、可观测和可恢复，不以绕过限流、网站条款或付费授权换取表面覆盖率。
4. 十个平台仍为 Amazon、TEMU、SHEIN、AliExpress、Shopee、eBay、Coupang、Ozon、Joybuy 和 TikTok Shop，范围为全球。
5. 已有合规审核结果继续有效；`denied` 与 `authorization_required` 不会因本次整改自动变成可采集。

## 目标

让本机机器人具备可持续测试的第一版运行能力：登录 Windows 后自动启动采集、分析、日报、预警和问答；能安全探测已审核但临时禁用的媒体发现源；为未来获准的媒体正文打通存储链路；清楚显示十个平台覆盖缺口；让飞书内容更通俗、依据更透明；降低长文、模型格式和超时造成的分析失败。

## 技术栈与命令

- Python：`>=3.11,<3.13`
- 配置：Pydantic Settings 2.x
- 数据库：SQLAlchemy 2.x + SQLite/aiosqlite
- 调度：APScheduler 3.x + Windows Task Scheduler
- 测试：`C:\Users\AKSSINA\.python\python.exe -m pytest`
- 静态检查：`C:\Users\AKSSINA\.python\python.exe -m ruff check .`
- 差异检查：`git diff --check`

## 设计

### 1. 稳定启动

新增一个前台运行脚本，设置非敏感运行开关：Cloudflare DoH、采集调度、AI 分析、日报、预警、问答、INFO 日志和 60 秒模型超时。脚本不读取或输出 `.env`，应用仍由 Pydantic 在进程内读取现有密钥。另一个安装脚本注册当前用户登录触发的 Windows 计划任务，设置 `IgnoreNew` 防止重复实例，并配置失败重启。若同名任务已存在且不是本项目，安装脚本拒绝覆盖。

### 2. GDELT 可恢复探测

常规定时任务继续遵守 `enabled=false`。管理 CLI 新增显式 `probe --source <id>`：只允许 `compliance=allowed` 的禁用来源做一次手工探测，不修改注册表、不持久化启用状态，也不放宽 HTTPS、DNS、SSRF、响应大小、重试和出版机构目录限制。HTTP 429 在重试耗尽后输出 `rate_limited`，而不是模糊的 `retry_exhausted`。

### 3. 获准媒体正文技术通路

媒体目录仍是不可由网络响应修改的代码白名单。仅 `allowed_public` 的出版机构能从 GDELT 元数据跟进公开原文；`licensed_api` 仍必须通过未来的专用授权连接器，不能借用 GDELT 网页抓取。存储层允许保存经过目录闸门产生的 `full_text` 媒体材料，从而消除当前“采集器能产生、持久层却拒绝”的断点。没有任何出版机构会在本次整改中被擅自改成 `allowed_public` 或 `licensed_api`。

### 4. 十个平台覆盖矩阵

CLI 新增按平台聚合的 `coverage` 输出，每个平台只显示：可用来源数、需授权数、待审核数、禁止数、总候选数和覆盖状态。第一版不把企业母公司新闻、搜索结果或未审核网页冒充卖家政策来源。现有七个允许来源继续运行；TEMU、SHEIN、AliExpress、Shopee、Ozon 与 TikTok Shop 的缺口保持显式，等待官方订阅源、授权 API 或后续逐站审核。

### 5. 飞书卡片解释性

当材料含媒体字段时，卡片显示中文“来源类型”和“分析依据”。`global_authority`、`specialist`、`chinese_industry` 以及 `full_text`、`feed_summary`、`metadata_only` 使用面向运营人员的中文说明。普通官方来源不显示空标签。原文链接、判断依据、风险等级、置信度、不确定性和建议动作继续保留。

### 6. AI 失败收敛

超过 50,000 字符的正文不再直接失败；分析器固定保留前 35,000 字符与后 14,998 字符，中间用两个换行分隔，确保送模内容不超过 50,000 字符。所有证据与事实仍必须锚定到实际送模摘录。模型结构化输出最多尝试三次：第一次正常生成，后两次只携带安全错误码和字段路径修复，不回传失败原文。运行脚本把 DeepSeek 超时从默认 30 秒提高到 60 秒；数据库原有跨批次重试策略不扩大，避免失控成本。

## 测试策略

- PowerShell：语法解析测试、脚本静态安全断言和计划任务定义检查。
- 采集：禁用且允许的来源仅在显式 probe 下运行；待授权/禁止来源即使 probe 也拒绝；429 返回 `rate_limited`。
- 持久化：完整媒体 provenance 可保存 `full_text`，缺失字段和未知范围仍拒绝。
- 覆盖：十个平台每个平台恰好一行，计数与来源注册表一致。
- 卡片：媒体中文标签出现在卡片和文本降级内容中；恶意字段继续被转义。
- AI：长文摘取边界、首尾保留、证据锚定、三次纠错和失败上限均有单元测试。
- 最终运行全量 pytest、Ruff、`git diff --check`，再做本机计划任务与单进程验收。

## 边界

- 始终：使用现有合规闸门；网络内容和 LLM 输出均视为不可信；所有新行为先有失败测试；不泄露密钥。
- 需另行授权：启用新的外部网站、接入商业媒体 API、写入新的 API 凭据、覆盖不属于本项目的同名计划任务。
- 永不：改写 `.env`；绕过 429、登录、验证码、付费墙、robots 或条款；把元数据当正文；把媒体报道当平台已确认政策。

## 验收标准

1. Windows 计划任务存在、动作为本项目脚本、当前用户登录触发、重复实例被抑制、失败可重启。
2. 机器人重启后仅一个实例，采集和智能调度器均启动。
3. 禁用的 GDELT 可被显式安全探测，429 明确显示为 `rate_limited`，且探测后仍保持禁用。
4. 获准媒体全文可通过现有 GDELT 目录闸门进入存储；未获准媒体仍不能抓正文。
5. `coverage` 对十个平台给出准确、可读的合规覆盖矩阵。
6. 飞书卡片在有媒体元数据时显示来源类型和分析依据。
7. 超长正文不再产生 `input_too_large`；格式修复最多三次；启动超时为 60 秒。
8. 全量测试和静态检查通过，没有新密钥或 `.env` 进入 Git。

## 未决问题

无阻塞性未决问题。GDELT 是否解除 429、哪些媒体取得正文授权、哪些平台提供可合法自动访问的新入口，属于外部状态，不作为第一版代码完成条件。
