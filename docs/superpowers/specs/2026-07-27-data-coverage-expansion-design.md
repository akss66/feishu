# 十平台数据覆盖扩展设计

日期：2026-07-27

状态：用户已确认，待实施计划

适用范围：本机运行的飞书跨境电商情报机器人

## 1. 背景

机器人当前登记 36 个候选渠道，但只有 7 个来源同时满足 `allowed + enabled`：

- 7 个已启用；
- 8 个官方来源待审核；
- 13 个来源需要书面授权、账号或许可；
- 7 个来源因条款限制明确禁用；
- 1 个 GDELT 媒体发现源已允许但尚未启用。

现有启用来源主要覆盖 Amazon、eBay、Coupang 和 Joybuy。TEMU、SHEIN、AliExpress、
Shopee、Ozon 和 TikTok Shop 仍可能在日报中长期没有有效材料。目标不是单纯增加登记数量，
而是扩大可以稳定采集、保留原文、由 LLM 分析并在日报中引用的真实覆盖。

## 2. 已确认目标

第一版采用“平台覆盖优先 + 提高每日信息量”的组合目标：

1. 覆盖 Amazon、TEMU、SHEIN、AliExpress、Shopee、eBay、Coupang、Ozon、Joybuy 和
   TikTok Shop；
2. 每个平台至少有 2 个有效来源；
3. 每个平台优先形成一条官方通道和一条独立的权威外部媒体通道；
4. 第一版只依赖免费公开来源，同时预留付费媒体全文 API 接口；
5. 只有可以合规取得的完整正文进入 LLM 深度分析；
6. 继续在本机运行，不迁移到云服务器；
7. 单一来源失败不得阻止其他来源采集或每天 09:00 的飞书日报。

第一版平台范围固定为上述 10 个平台。Lazada 和 Mercado Libre（美客多）不进入本期登记、覆盖计数
或验收；它们只作为后续扩展候选，不能分散本期 `10 × 2` 的交付目标。

## 3. “有效来源”的严格定义

一个来源只有同时满足以下条件，才能计入某个平台的 `2/2` 覆盖：

1. 在来源登记表中拥有稳定、唯一的 `source_id`；
2. 合规状态为 `allowed`，并且 `enabled=true`；
3. 具有可复核的条款、robots、授权或订阅依据；
4. 通过离线样本测试；
5. 通过一次显式、单篇或单批次的真实采集冒烟；
6. 能稳定输出发布日期、标题、原文链接、平台标签和内容等级；
7. 最近三次计划采集没有连续失败；
8. 若计入媒体通道，必须能在允许范围内取得完整正文，且出版机构与官方通道相互独立。
9. 若一个综合媒体声称覆盖多个平台，必须在最近 90 日材料或真实冒烟中确认该平台确有合格内容，
   才能计入该平台的媒体覆盖。

GDELT、搜索结果页和只提供标题或摘要的新闻 API 是发现通道，不是媒体出版机构。它们本身不计入
`2/2`。通过发现通道找到的原始媒体，只有单独完成出版机构审核并取得完整正文后，才能作为独立
媒体来源计数。

同一篇文章经多个渠道重复发现，只能算一篇材料。一个媒体集团在多个入口重复发布同一正文时，
默认只算一个独立出版机构，不能通过增加入口虚增覆盖。

## 4. 选择的方案

采用“官方 + 权威媒体双通道”，不采用纯媒体优先或账号/API 优先。

### 4.1 官方通道

允许的官方通道包括：

- 平台明确发布的 RSS、公开 API 或 changelog；
- 条款允许低频自动访问的公开新闻、政策或帮助页面；
- 用户合法订阅并明确允许内部处理的官方邮件或 newsletter；
- 官方集团新闻、投资者公告或交易所公开披露。
- 经过来源允许名单核验后，由团队成员转发到飞书的官方公众号文章；
- 通过官方 API、Webhook、邮件通知或人工导出取得的卖家后台通用公告。

条款明确禁止机器人、抓取或系统性索引的网页继续保持 `denied`。不得用浏览器自动化、登录态、
Cookie、代理、更换身份、隐藏 User-Agent 或忽略重定向循环来绕过限制。

官方公众号和卖家后台通知不能作为普通网页采集：

- 公众号不假设存在可批量读取的公开接口。第一版只接受团队成员主动转发的文章、正文或附件；
- 转发的公众号文章必须验证 `mp.weixin.qq.com` 原始链接和已登记的官方账号名称；
- 卖家后台不保存账号密码、Cookie 或浏览器会话，只接受官方 API/Webhook、专用邮箱通知或人工导出；
- 邮件优先使用 OAuth；必须使用 IMAP 授权码时，仅保存在 `.env`，不进入数据库、日志或 Git；
- 后台通知只接收政策、费用、类目、活动和通用合规公告。订单、余额、买家、店铺处罚和其他
  账号私密数据默认拒绝进入日报链路；
- 用户主动转发只授权机器人进行内部分析，不意味着获得公开转载全文的许可。飞书日报只展示摘要、
  必要证据和原始链接，不复制整篇材料。

### 4.2 权威媒体通道

第一版只接入明确允许自动读取和内部分析的免费 RSS、公开 API 或公开全文。来源审核必须记录：

- 出版机构；
- 内容许可范围；
- 是否允许保存全文；
- 是否要求署名；
- 是否允许商业或内部自动化使用；
- 最近复核日期。

未来付费媒体 API 使用稳定的 `LicensedNewsProvider` 接口接入。付费实现必须返回与免费来源相同的
标准文档对象，不能让日报、分析器或去重器依赖某一家供应商。

### 4.3 发现与监管补充

GDELT 按十个平台拆成独立的有界查询，只保存标题、出版机构、发现时间和原文链接。原始出版机构
不在允许名单时，不请求正文。遇到 429 时遵守 `Retry-After` 并退避，不并发轰击。

政府、监管机构、交易所和产品召回来源属于权威外部证据，可以提高风险判断质量，但不代替每个平台
所需的权威媒体通道。只有材料明确提及平台或经过可复核映射时，才能关联到该平台。

全文分析，也不计入 `2/2`。

## 6. 内容等级与 LLM 边界

所有采集结果在入库时固定标记为以下三档之一：

### 6.1 `full_text`

包含可合法保存和处理的完整正文。只有这一档可以进入 LLM，生成：

- 通俗中文摘要；
- 影响平台、站点和卖家类型；
- 风险等级；
- 置信度；
- 判断依据；
- 可执行建议；
- 原文链接和证据引用。

判断依据必须能在保存的原文中定位。无法定位的结论不得进入日报。

### 6.2 `feed_summary`

只包含出版机构提供的摘要。可以出现在“新闻线索”区，但必须标注“仅摘要，待核实”，不得产生风险
结论、置信度或操作建议。

### 6.3 `metadata_only`

只包含标题、时间、出版机构和原文链接。只能用于发现、去重和后续人工审核，不进入日报主体，
也不调用 LLM。

## 7. 架构与数据流

```text
来源登记表
  -> 合规门禁
  -> RSS / API / HTML / OfficialNoticeProvider / ManualSubmission / LicensedNewsProvider
  -> 原始快照与内容等级
  -> URL 规范化、正文指纹和跨来源事件聚类
  -> 平台、地区和语言分类
  -> full_text LLM 分析
  -> 证据校验和风险策略
  -> 日报选择、覆盖摘要和来源异常
  -> 飞书 Outbox 幂等发送
```

各组件保持单一职责：

- 来源登记表只描述来源、许可、覆盖和采集参数；
- 采集器只负责获取与规范化材料；
- `OfficialNoticeProvider` 只接收官方 API、Webhook 或专用邮箱中的通用公告；
- `ManualSubmission` 接收飞书中主动转发的公众号文章、正文或附件，并保留提交人和原始来源审计；
- 合规门禁决定是否允许请求和允许保存到什么范围；
- 去重器负责同文与同事件合并；
- 分类器负责平台、地区和语言标签；
- LLM 分析器只消费 `full_text`；
- 日报编排器只消费已验证分析和安全的线索摘要；
- 交付层继续使用现有 Outbox 和日报日期幂等键。

## 8. 调度与 09:00 日报

常规采集继续每两小时运行。为避免机器人启动时间导致最后一次采集落在 09:00 之后，增加独立的日报
预处理流程：

1. 08:40 启动日报前采集；
2. 每个来源受独立超时和全局并发限制；
3. 08:55 停止等待未完成来源，将其标记为本次覆盖缺失；
4. 08:55 至 08:59 完成待分析队列、证据校验和日报组装；
5. 09:00 使用既有幂等键发送一次；
6. 未完成来源在后续常规周期继续采集，不能阻塞日报。

日报窗口语义仍为前一日 09:00（含）至当日 09:00（不含）。08:40 后才发布但未能在截止前完成采集
的内容进入下一份日报，不回填或修改已发送日报。

本机必须保持开机、用户已登录且网络可用。第一版不承诺电脑关机、休眠或断网期间仍能准时发送。

## 9. 日报展示

日报主体继续按风险与证据质量选择真实条目，不为凑数加入旧闻。新增两个简短区块：

### 9.1 今日覆盖

显示：

- 平台覆盖数量，例如 `8/10`；
- 有效来源数量，例如 `17/20`；
- 每个平台 `2/2`、`1/2` 或 `0/2`；
- 完整正文、摘要线索和元数据线索的数量。

### 9.2 来源异常

只显示对用户有意义的说明，例如：

- “Ozon 第二来源今日超时，本次日报为部分覆盖”；
- “TEMU 媒体来源仅返回摘要，未进入 AI 结论”；
- “SHEIN 暂无合规完整正文来源”。

不得把堆栈、内部 URL 参数、密钥、Cookie、群 ID 或原始模型输出写入飞书卡片。

## 10. 去重与多平台归因

依次使用以下键去重：

1. 清理追踪参数后的规范化原文 URL；
2. 规范化标题、出版机构和发布日期；
3. 正文指纹；
4. 相同事件的跨媒体聚类。

同一材料可以关联多个平台，但日报只展示一次，并列出涉及平台。聚合器和原始媒体重复发现同一文章时，
保留原始出版机构作为来源，聚合器只保留发现审计记录。

LLM 不得自行增加原文未提及的平台。平台归因必须来自来源注册、明确文本证据或受测试的确定性映射。

## 11. 故障处理

- 单个来源失败与其他来源隔离；
- 网络超时、5xx 和 429 使用有上限的退避重试；
- 401、403、验证码、登录跳转和条款禁止不重试绕过；
- 连续三次计划采集失败后自动暂停来源，等待人工复核；
- 条款或 robots 内容发生实质变化时转为 `pending_review`；
- 正文提取失败时降级到实际可用的 `feed_summary` 或 `metadata_only`，不能伪造正文；
- 解析结构改变时保留快照和安全错误码，不把异常 HTML 送入 LLM；
- 官方通知进入分析前移除店铺 ID、订单、余额、买家信息、邮箱和其他账号级敏感数据；
- 无法确认官方公众号身份、原始链接或转发完整性时降级为待人工复核；
- 某个平台当天没有更新时明确显示“无已验证更新”；
- 已发送日报保持不可变；迟到材料进入下一窗口。

## 12. 测试与验收

### 12.1 每来源测试

每个候选来源必须具有：

- 登记表 schema 测试；
- 固定离线样本；
- 标题、时间、正文、语言和链接解析测试；
- 内容等级测试；
- 禁止登录、重定向绕过和超大响应测试；
- 单篇或单批真实冒烟测试。

### 12.2 跨来源测试

- 同一 URL 多入口去重；
- 不同 URL 同正文去重；
- 聚合器与原始媒体合并；
- 一篇文章关联多个平台但日报只出现一次；
- 摘要和元数据不调用 LLM；
- 引用可以在原文定位；
- 未知出版机构被拒绝抓正文。
- 同一官方公告经公众号、邮件和后台重复到达时只保留一个事件；
- 公众号伪造名称、非 `mp.weixin.qq.com` 链接和未登记账号被拒绝；
- 后台通知中的店铺、订单、余额和个人信息在调用 LLM 前完成脱敏；

### 12.3 调度与交付测试

- 使用假时钟验证 08:40 预处理和 09:00 发送；
- 来源超时不会阻止日报；
- 重启后同一日报日期不会重复发送；
- 迟到材料进入下一日报窗口；
- 飞书卡片正确显示覆盖缺口；
- Outbox 重试仍保持单消息幂等。

### 12.4 上线成功门

第一版上线必须同时满足：

1. 十个平台均有覆盖记录；
2. 每个平台达到 `2/2`；如果合规免费来源不足，停止上线并由用户重新决定目标或授权方案；
3. 所有计数来源均满足第 3 节的有效来源定义；
4. 至少连续三次计划采集没有新增持续失败；
5. 完成一次不发送的 09:00 全流程演练；
6. 完成一次测试群确认发送；
7. 日志和飞书卡片不含秘密或正文；
8. 所有测试、静态检查和编译检查通过。

## 13. 分阶段实施

### 阶段一：覆盖可观测性

增加平台 `0/2`、`1/2`、`2/2` 状态、内容等级统计和来源暂停原因。先让实际缺口可见。

### 阶段二：免费官方来源

逐个平台审核、增加离线样本、运行单篇冒烟并启用。优先处理目前完全空白的平台，不一次性批量启用。

### 阶段三：官方通知入口

实现 `OfficialNoticeProvider` 和 `ManualSubmission`，先接飞书人工转发，再接专用邮箱。邮箱接入必须
完成 OAuth/授权码秘密管理、附件上限、发件人允许名单、账号级数据拒绝和脱敏测试。

### 阶段四：免费媒体与发现层

把 GDELT 拆成十个平台查询，增加出版机构允许名单和正文许可审核。只有通过审核的原始媒体才计入
媒体覆盖。雨果跨境、亿恩网、出海网、电商报和网经社按第 5.2 节逐家复核，不批量启用。

### 阶段五：日报预处理与覆盖展示

实现 08:40 预处理、09:00 幂等发送、覆盖摘要和部分覆盖提示。

### 阶段六：付费接口预留

定义并测试 `LicensedNewsProvider` 空实现和契约测试，不购买、不调用任何付费服务。用户观察第一版
效果后再决定供应商和预算。

## 14. 不在第一版范围

- 购买付费媒体或代表用户签署授权协议；
- 绕过网站条款、robots、登录、验证码、区域限制或反爬措施；
- 使用登录 Cookie 自动抓卖家后台；
- 自动批量读取微信公众号历史文章；
- 启用生产浏览器采集；
- 迁移到云服务器或实现高可用；
- 抓取社交平台评论、论坛舆情或个人数据；
- 扩展 Lazada 或 Mercado Libre；
- 商品、价格、评论和竞品销量的规模化采集；
- 自动执行封店、下架、调价或广告操作。

## 15. 已确认的产品决策

- 优先级：平台全覆盖与信息量同时重要；
- 覆盖目标：每个平台至少 2 个有效来源；
- 来源结构：官方 + 权威媒体双通道；
- 正文原则：保留原文并由 LLM 分析，摘要和元数据不冒充原文；
- 媒体预算：第一版免费，预留付费接口，观察效果后再决定；
- 中文媒体候选：雨果跨境、亿恩网、出海网、电商报和网经社，均先审核后启用；
- 官方通知：公众号和卖家后台通过 API、邮件或人工转发接入，不自动登录抓取；
- 平台范围：本期只做原 10 个平台，不加入 Lazada 和 Mercado Libre；
- 部署方式：继续本机运行；
- 日报行为：无更新时明确说明，不使用旧闻或无来源内容填充。
