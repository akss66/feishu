# GDELT 受控原文二次抓取设计

日期：2026-07-27
状态：待用户书面复核
范围：Amazon、TEMU、SHEIN、AliExpress、Shopee、eBay、Coupang、Ozon、Joybuy、
TikTok Shop

## 目标

启用十个平台对应的 GDELT 新闻发现源，并对 GDELT 返回的原文链接执行受控二次抓取。
只有取得完整、可信且相关的正文后才允许进入 AI 分析；无法取得正文的记录保留为
“待核实线索”，不得生成确定性风险结论。

本设计扩大媒体报道覆盖，但不把媒体报道计作官方公告，也不承诺每个平台已经达到
2 个有效全文发布者的严格覆盖目标。

## 非目标

- 不绕过登录墙、付费墙、验证码、反机器人措施或访问控制。
- 不登录卖家后台，不采集账户、订单、买家或其他敏感数据。
- 不长期保存媒体文章全文。
- 不因为 GDELT 收录了链接，就自动把该媒体标记为已授权全文来源。
- 不在本阶段接入浏览器自动化或采购商业新闻数据。

## 方案

### 1. 新闻发现

启用现有 10 个 `media-gdelt-*` 来源。每个平台使用独立查询，GDELT 返回的标题、媒体、
发布时间、原文 URL 和平台关联作为发现记录保存。

发现记录的内容等级仍为 `metadata_only`。只有二次抓取成功并通过全部准入检查后，派生记录
才能升级为可分析正文；启用 GDELT 本身不会直接提升严格全文覆盖数。

### 2. URL 安全检查

二次抓取前必须：

- 只接受 `https` 原文 URL。
- 拒绝带用户名或密码的 URL。
- 解析主机名并拒绝回环、私网、链路本地、保留地址和云元数据地址。
- 每次重定向后重新执行相同检查，最多允许 3 次重定向。
- 拒绝非标准 Web 端口。
- 使用项目现有请求客户端的超时、并发和逐域名频率限制。
- 响应正文上限为 10 MiB；超限立即停止。
- 只接受明确的 HTML/XHTML 媒体类型。

DNS 解析失败、证书错误、重定向越界或目标变为非公网地址时，记录安全错误码，不在用户卡片
中暴露内部网络信息。

### 3. 访问控制与降级

以下情况不重试绕过，直接降级为待核实线索：

- HTTP 401、403、407、429。
- 登录、订阅或付费墙。
- CAPTCHA、JavaScript challenge 或明确的机器人验证页。
- robots 或来源策略禁止自动访问。
- 正文需要执行浏览器脚本才能获得。

5xx、连接超时和临时 DNS 失败可以按现有退避策略有限重试；达到上限后同样降级，不阻断其他
来源。

### 4. 正文提取和质量门

HTML 通过现有正文提取器去除导航、广告、页脚、推荐内容和评论。派生正文必须同时满足：

- 标题非空。
- 正文达到最小有效长度。
- 正文不是错误页、登录页、验证码页或站点导航集合。
- 标题或正文与指定平台存在明确关联。
- 能确定原始媒体域名、原文 URL、抓取时间和 GDELT 发现来源。
- 正文内容指纹未与已有文章重复。

同一文章被多个 GDELT 查询或其他来源发现时只分析一次，但保留全部平台和来源关联。

### 5. AI 准入和输出

通过质量门的正文只在当前处理流程中交给 LLM，并生成：

- 通俗摘要。
- 涉及平台与站点。
- 风险等级和置信度。
- 判断依据。
- 建议动作。
- 原文链接和媒体归属。

数据库长期保留派生摘要、必要的短证据片段、内容指纹、媒体归属和原文链接，不长期保存整篇
媒体正文。未通过质量门的发现记录不调用 LLM，只进入“待核实线索”。

媒体报道和官方公告在日报中分区展示。媒体内容必须使用“媒体报道/据原文”措辞，不得写成
平台已正式发布政策。

### 6. 来源状态

来源启用遵循以下规则：

- `allowed` 且技术验证通过：启用。
- `pending_review`：完成条款、robots、正文质量和近 90 天相关性检查后才能启用。
- `authorization_required`：取得明确授权前保持禁用。
- `denied`：保持禁用，不尝试绕过。

GDELT 发现源可以启用为元数据雷达；原文是否进入 AI 由每篇文章的 URL、访问控制、内容质量
和来源策略共同决定。

## 数据流

1. 定时任务查询 10 个 GDELT 平台源。
2. 保存并去重元数据发现记录。
3. 安全验证原文 URL。
4. 受控 HTTP 抓取原文。
5. 检测访问墙和错误页。
6. 提取正文并执行完整性、相关性和重复性检查。
7. 成功正文进入 AI；失败记录进入待核实线索。
8. 日报分别展示官方公告、媒体分析、待核实线索和来源异常。

## 运行保护

- 全局并发和逐域名并发分别受限。
- 对单域名设置最小请求间隔。
- 每轮限制 GDELT 候选数和原文抓取数，避免一次性放大请求。
- 单篇正文仍受现有 50,000 字符 LLM 输入上限约束。
- 抓取错误只记录稳定错误码和目标域名，不记录正文、凭据或完整查询参数。
- 二次抓取提供独立开关；关闭后 GDELT 仍可只作为线索源运行。
- 达到异常率、429 比例或抓取耗时红线时，自动停止该域名本轮抓取并告警。

## 配置

新增配置使用保守默认值：

- GDELT 十平台发现源默认启用。
- 原文二次抓取总开关默认关闭，完成真实 smoke 后人工启用。
- 每轮候选数、并发、逐域名间隔、超时、正文大小和重定向次数均有固定上限。
- 配置不得允许关闭私网地址检查、响应大小限制或访问墙检测。

## 测试与验收

### 离线测试

- 10 个 GDELT 来源均能加载并保持 `metadata_only`。
- URL 安全测试覆盖公网、私网、重定向到私网、危险端口和超限重定向。
- 响应测试覆盖 HTML、错误媒体类型、超大正文、压缩炸弹边界和异常字符集。
- 访问墙测试覆盖 401、403、407、429、登录页、付费墙和验证码页。
- 正文质量测试覆盖有效文章、导航页、空正文、短正文和无关文章。
- 去重测试证明同一 URL、规范化 URL 和相同正文只分析一次。
- 数据保留测试证明整篇媒体正文不会长期写入数据库。
- 卡片测试证明媒体、官方和线索分区明确。

### 真实网络 smoke

真实网络验证必须显式启用。每个平台最多选择少量候选，每个 URL 只请求一次，不并行轰击
同一域名。记录：

- GDELT 查询是否成功。
- 原文是否为公开 HTTPS 页面。
- HTTP 状态和媒体类型。
- 是否检测到访问墙。
- 是否提取到完整且相关正文。
- 最终结果为 `analyzable` 或 `lead_only`。

真实 smoke 不自动修改来源合规状态。只有证据写入验收文档且评审通过后，才打开生产二次
抓取开关。

## 成功标准

- 10 个 GDELT 平台发现源均进入定时发现流程。
- 任一抓取失败不会阻断其他平台或 09:00 日报。
- 只有完整且相关的正文调用 LLM。
- 登录墙、付费墙、验证码和受限页面均不会被绕过。
- 日报明确区分官方事实、媒体分析和待核实线索。
- 所有离线测试和代码检查通过。
- 真实 smoke 结果如实记录，不以候选数量冒充有效全文覆盖。

## 回退

关闭原文二次抓取开关后，系统立即恢复为 GDELT 只发现线索的模式；必要时可再禁用单个平台
的 GDELT 来源。回退不删除发现记录、审计日志或已生成的日报。
