# 日报测试隔离与安全补发设计

日期：2026-07-23

## 背景与根因

2026-07-23 09:00 的日报任务准时触发，但没有进入飞书发送队列。只读数据库和运行日志证明：

- 2026-07-22 13:52 的人工测试已经把 `2026-07-23` 日报标记为 `sent`；
- 该测试占用了正式幂等键 `daily:<group>:2026-07-23`；
- 09:00 调度再次生成同一日期时触发 `ReportAlreadySent`；
- 防重复保护本身工作正确，错误在于测试发送与正式发送共用了同一记录和幂等命名空间。

## 目标

1. 立即以可审计、不可重复的“补发”通道发送 2026-07-23 的完整窗口日报。
2. 人工测试不能再占用正式日报记录或正式幂等键。
3. 正式发送命令不能在日报统计窗口尚未结束时提前发送未来日报。
4. 保留昨天已发送的测试记录，不删除、不改写历史审计数据。
5. 次日 09:00 自动日报继续使用原有正式幂等键并只发送一次。

## 方案比较

### 方案 A：重置昨天的已发送记录

把 `daily_reports` 和 `delivery_outbox` 的已发送状态改回待发送并覆盖载荷。实现最快，但会改写历史事实、混淆已发送消息与补发消息，因此不采用。

### 方案 B：测试、正式、补发三个命名空间（采用）

- 正式：`daily:<group>:<date>`；
- 测试：`daily-test:<group>:<date>:<payload-digest>`；
- 补发：`daily-correction:<group>:<date>:<payload-digest>`。

测试和补发直接把可信的日报草稿载荷写入 outbox，不创建或更新正式 `daily_reports` 记录。相同载荷重复执行仍保持幂等。补发卡片标题明确显示“补发”，测试卡片标题明确显示“测试”。该方案保留全部审计证据，也不会影响次日自动发送。

### 方案 C：所有发送都使用时间戳编号

可以绕过冲突，但会失去正式日报“一天一份”的防重复保证，因此不采用。

## 设计

### 日报构建与持久化分离

`DailyReportService` 增加只负责查询、筛选和组合内容的草稿构建路径。现有 `preview` 仍会保存正式日报；测试和补发只使用草稿构建路径，不写入 `daily_reports`。

### 测试发送

CLI 新增：

```text
python -m commerce_agent.intelligence_cli report test-send --date YYYY-MM-DD --confirm
```

它生成当时可用的日报草稿，给标题添加“测试”，使用 `daily-test:` 幂等键入队并立即走现有飞书投递器。它不得占用 `daily:` 正式键。

### 正式发送保护

现有 `report send` 在执行前计算目标日报窗口结束时间。若当前时间早于窗口结束时间，返回受控错误 `report_window_open`，不得把当天尚未结束或未来日期标记为正式已发送。

### 安全补发

CLI 新增：

```text
python -m commerce_agent.intelligence_cli report resend --date YYYY-MM-DD --confirm
```

它重新读取完整窗口资料、生成新草稿、给标题添加“补发”，使用 `daily-correction:` 幂等键入队并立即发送。原正式日报及昨天测试发送记录保持不变。

### 调度幂等

自动调度遇到 `ReportAlreadySent` 时记录为幂等跳过，不再记为任务故障；其他异常仍按现有方式记录错误。

## 安全与失败处理

- `test-send` 和 `resend` 都必须显式提供 `--confirm`。
- 变体只能是封闭集合 `test` 或 `correction`，未知值拒绝。
- 幂等摘要基于规范化后的可信日报载荷，不包含密钥或群聊明文日志。
- 飞书失败仍进入现有 outbox 重试状态，不绕过投递审计。
- 不直接修改已有 `sent` 记录，不进行数据库迁移。

## 测试与验收

1. 先写回归测试证明：当前 `report send` 会错误允许窗口未结束的未来日报。
2. 验证修复后返回 `report_window_open`，且未调用正式入队。
3. 验证测试发送使用 `daily-test:`，不会创建或修改正式日报。
4. 验证补发使用 `daily-correction:`，相同内容重复操作不会重复发送。
5. 验证调度遇到 `ReportAlreadySent` 视为幂等完成。
6. 运行完整 pytest、Ruff 和差异检查。
7. 先预览 2026-07-23 补发内容，再执行一次补发；只读查询确认 outbox 为 `sent`，并确认飞书消息 ID 已记录。
